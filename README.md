# Telegram Bot with Whisper Transcription

Telegram бот для загрузки видео и их транскрипции с помощью Whisper AI.

## 🤖 Как работает бот

Всё управление — инлайн-кнопками, команды дублируют их один в один.

1. `/start` — короткое приветствие и меню:
   **📝 Транскрибировать · 📥 Скачать · 📤 Загрузить файлы · 📊 Статус · ❓ Помощь**
2. Нажатие **Транскрибировать** или **Скачать** → «🔗 Пришлите ссылку…»
3. Пользователь присылает ссылку → «✅ Всё запущено, ожидайте.»
4. По готовности приходит результат: расшифровка файлом или ссылка на скачанное видео
   (ссылка живёт 24 часа, файл до 50 МБ дополнительно кладётся в чат вложением).

Порядок можно и обратить: если сначала прислать ссылку, бот придержит её и покажет
кнопки выбора — работа стартует сразу после нажатия.

При выборе **Скачать** бот сперва спрашивает формат — 🎵 аудио или 🎬 видео,
и только потом просит ссылку.

Голосовые, аудио и видео до 20 МБ можно слать прямо в чат — они уходят в транскрипцию
без выбора действия. Файлы крупнее Telegram боту не отдаёт, для них бот выдаёт
одноразовую ссылку на форму загрузки.

Для транскрипции скачивается только звуковая дорожка: Whisper всё равно
использует лишь её, а полное видео того же ролика весит на порядок больше.

### Форматы расшифровки

Готовый текст приходит файлом, а под ним — кнопки остальных форматов:

| Кнопка | Что это |
|---|---|
| 🎬 Субтитры SRT | для видеоредакторов и плееров |
| 🌐 Субтитры VTT | для веб-плееров и YouTube |
| 📝 Word | `.docx`, каждая реплика — абзац; собирается при нажатии |

Субтитры достаются бесплатно: Whisper за тот же проход кладёт рядом с текстом
`.srt`, `.vtt`, `.json` и `.tsv` — второй раз считать нечего. Кнопками, а не
четырьмя вложениями подряд, потому что нужны они не каждому.

Язык бот определяет сам. Раньше он был зашит, и русская запись при английской
настройке **переводилась** вместо расшифровки — это было незаметно ровно до
первой записи не на том языке.

## 🗄 База данных

Очередь задач живёт в Postgres, а не в памяти: раньше перезапуск бота молча
съедал всё, что не успело обработаться, — пользователь ждал расшифровку,
которой уже никто не занимался.

```bash
docker compose up -d postgres     # поднять базу (порт 5433, только localhost)
docker compose logs -f postgres   # если бот жалуется на подключение
```

Схему создаёт **только** Flyway (`src/main/resources/db/migration`), Hibernate
её лишь сверяет. Расхождение схемы и кода валит приложение на старте — это
намеренно: лучше не запуститься, чем сломаться на первой же задаче.

Порт 5433, а не стандартный 5432, потому что на машине разработки обычно уже
крутится чей-то Postgres. Задаётся через `DB_PORT` (см. `env.example`).

| Таблица | Что хранит |
|---|---|
| `jobs` | очередь и история задач: кто заказал, что делать, чем кончилось |
| `download_tokens` | выданные ссылки на скачивание и их срок годности |
| `accounts` | аккаунты сайта (вход появится вместе с сайтом) |

Владелец задачи — пара «тип + идентификатор» (`TELEGRAM` или `ACCOUNT`),
а не chat id: у аккаунта на сайте чата не будет вовсе.

## 🚀 Автозапуск

Бот поднимается сам после перезагрузки — служба systemd (база стартует
раньше, вместе с Docker):

```bash
sudo bash deploy/home/setup-service.sh      # поставить или обновить
systemctl status transcribot                # что с ним сейчас
journalctl -u transcribot -n 50             # если не стартует
```

Скрипт идемпотентный и сам гасит бота, запущенного руками, — иначе тот займёт
порт 8080 и служба не поднимется.

## 📋 Логи

| Куда | Что |
|---|---|
| консоль и `logs/app.log` | ход дела, уровень задаётся `LOG_LEVEL` (по умолчанию INFO) |
| `logs/jobs/job-<id>.log` | всё по одной задаче, включая построчный вывод yt-dlp и Whisper |

Отдельный файл на задачу нужен потому, что при параллельных заданиях общий лог
перемешивается. Пока идёт распознавание, бот раз в 30 секунд пишет строку вида
`Whisper работает: 2 мин 30 с, распознано сегментов=118` — по ней видно, что
процесс жив, а не завис. Если вывода нет дольше трёх минут, строка повышается
до WARN.

## 🧩 Две половины: приём и исполнение

Приложение одно, но собирается из двух половин, и какая из них поднята —
решает профиль Spring:

| Профиль | Что поднимает | Где живёт |
|---|---|---|
| `bot` | long polling Telegram, дальше сайт | VPS |
| `home` | очередь, база, файлы, yt-dlp, Whisper | домашняя машина |

По умолчанию активны **оба** (`spring.profiles.default=bot,home`) — это
привычный запуск на одной машине, и ничего настраивать не нужно.

Когда половины разъезжаются, всё, что боту нужно от дома, проходит через один
интерфейс `HomeApi`: дома его реализует `LocalHomeApi` прямым вызовом сервисов,
на VPS — `HttpHomeApi` запросом через WireGuard с общим ключом в заголовке.
Код бота разницы не видит.

Отправка в Telegram при этом доступна обеим сторонам: `getUpdates` Telegram
отдаёт одному процессу, а `execute` — обычный HTTPS-запрос, поэтому готовую
расшифровку отправляет дом, где лежит файл, а на кнопки отвечает VPS.

Спящая домашняя машина не мешает принять задачу: она ложится в спул на диске
VPS (файл на задачу — базы там нет) и уходит в работу при первом же успешном
обращении. Пользователь видит «принято, начнётся, когда машина проснётся», а
затем «машина проснулась, задачи пошли в работу». Порядок сохраняется: пока
спул не пуст, свежая задача тоже кладётся в него и не обгоняет ту, что ждёт
с ночи.

Отложить можно не всё: форму загрузки отдаёт дом, готовые файлы лежат у него —
на эти действия при спящей машине приходит «недоступно». Команды и порядок
шагов — в [deploy/README.md](deploy/README.md).

## 🌍 Публичный адрес для ссылок на файлы

Бот отдаёт скачанные файлы ссылкой вида `{DOWNLOAD_BASE_URL}/download/<токен>`.
Если базовый адрес недоступен извне, ссылка не откроется с телефона — это самая
частая причина «ссылка не работает». Проверять так, с устройства вне домашней
сети:

```bash
curl -I <адрес>/download/<токен>
```

Значение задаётся переменной `DOWNLOAD_BASE_URL` (см. `env.example`).
Оно должно указывать на адрес, доступный из интернета, — обычно это
дешёвый VPS-релей, проксирующий запросы на эту машину.

## 🚀 Быстрый старт

### Локальная разработка

1. **Клонируйте репозиторий:**
```bash
git clone <your-repo-url>
cd Bot
```

2. **Создайте .env файл:**
```bash
cp env.example .env
# Отредактируйте .env с вашими настройками
```

3. **Соберите JAR локально:**
```bash
./gradlew build
```

4. **Запустите с помощью скрипта:**
```bash
./build-and-run.sh full
```

### Развертывание на сервере

#### Подготовка сервера

1. **Установите Docker и Docker Compose:**
```bash
curl -fsSL https://get.docker.com -o get-docker.sh
sudo sh get-docker.sh
sudo usermod -aG docker $USER
```

2. **Клонируйте репозиторий на сервер:**
```bash
git clone <your-repo-url>
cd Bot
```

3. **Создайте .env файл на сервере:**
```bash
cp env.example .env
# Добавьте BOT_TOKEN, ADMIN_CHAT_ID и другие переменные
```

#### Настройка CI/CD

1. **Добавьте GitHub Secrets:**
   - `SERVER_HOST` - IP адрес сервера
   - `SERVER_USER` - пользователь для SSH
   - `SERVER_SSH_KEY` - приватный SSH ключ

2. **Настройте переменные окружения на сервере:**
```bash
export BOT_TOKEN="your-bot-token"
export ADMIN_CHAT_ID="your-admin-chat-id"
export GITHUB_REPOSITORY="your-username/your-repo"
```

3. **Первый деплой:**
```bash
./deploy.sh deploy
```

## 📋 Использование

### Локальная разработка

```bash
# Полная сборка и запуск
./build-and-run.sh full

# Только сборка
./build-and-run.sh build

# Только запуск
./build-and-run.sh run

# Предзагрузка моделей
./build-and-run.sh preload small,medium

# Просмотр логов
./build-and-run.sh logs

# Остановка
./build-and-run.sh stop
```

### Серверное развертывание

```bash
# Развернуть latest версию
./deploy.sh deploy

# Развернуть конкретную версию
./deploy.sh deploy v1.2.3

# Откатиться к предыдущей версии
./deploy.sh rollback v1.2.2

# Обновить образ без перезапуска
./deploy.sh update

# Предзагрузить модели
./deploy.sh preload small,medium

# Проверить статус
./deploy.sh status

# Просмотр логов
./deploy.sh logs
```

## 🔧 Конфигурация

### Переменные окружения

| Переменная | Описание | Обязательно |
|------------|----------|-------------|
| `BOT_TOKEN` | Токен Telegram бота | Да |
| `ADMIN_CHAT_ID` | ID чата администратора | Нет |
| `WHISPER_PRELOAD_MODELS` | Модели для предзагрузки | Нет |
| `WHISPER_DEVICE` | Устройство для Whisper (cpu/cuda) | Нет |
| `WHISPER_COMPUTE_TYPE` | Тип вычислений (int8/float16) | Нет |

### Модели Whisper

Доступные модели: `tiny`, `base`, `small`, `medium`, `large-v1`, `large-v2`, `large-v3`

Пример предзагрузки:
```bash
WHISPER_PRELOAD_MODELS="small,medium" ./deploy.sh deploy
```
