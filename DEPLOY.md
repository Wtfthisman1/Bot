# Деплой Telegram Bot

## Подготовка к деплою

### 1. Установка зависимостей

Убедитесь, что у вас установлены следующие инструменты:

```bash
# Java 17+
java -version

# rsync (для копирования файлов)
rsync --version

# sshpass (для автоматического подключения)
sshpass -V
```

### 2. Настройка переменных окружения

Скопируйте файл с примерами переменных:

```bash
cp env.example .env
```

Отредактируйте `.env` файл и установите необходимые значения:

```bash
# Обязательные переменные
BOT_TOKEN=your_bot_token_here
ADMIN_CHAT_ID=your_admin_chat_id_here

# URL для загрузок (замените на ваш домен или IP)
UPLOAD_BASE_URL=http://REDACTED_IP:8080
```

### 3. Настройка сервера

Убедитесь, что на сервере установлены:

- Docker
- docker-compose
- Git

## Проверка готовности к деплою

Перед деплоем запустите проверку:

```bash
./check-deploy.sh
```

Этот скрипт проверит:
- ✅ Локальную среду (Java, rsync, sshpass)
- ✅ Файлы проекта (build.gradle, docker-compose.yml, etc.)
- ✅ Переменные окружения (.env)
- ✅ Подключение к серверу
- ✅ Сборку проекта

## Запуск деплоя

Если все проверки пройдены, запустите деплой:

```bash
./deploy.sh
```

### Что делает скрипт деплоя:

1. **Проверяет зависимости** - убеждается, что все необходимые файлы и инструменты доступны
2. **Собирает проект** - выполняет `./gradlew clean bootJar`
3. **Коммитит и пушит** - сохраняет изменения в Git
4. **Проверяет сервер** - тестирует подключение и наличие Docker
5. **Копирует файлы** - синхронизирует код с сервером
6. **Обновляет код** - выполняет `git pull` на сервере
7. **Пересобирает контейнер** - останавливает, пересобирает и запускает Docker контейнер
8. **Проверяет статус** - показывает логи и статус контейнеров

## Мониторинг

После деплоя приложение будет доступно по адресу:
```
http://REDACTED_IP:8080
```

### Полезные команды для мониторинга:

```bash
# Статус контейнеров
docker-compose ps

# Логи приложения
docker-compose logs -f bot

# Перезапуск контейнера
docker-compose restart bot

# Остановка всех контейнеров
docker-compose down
```

## Устранение неполадок

### Ошибка "JAR файл не найден"

Убедитесь, что сборка прошла успешно:
```bash
./gradlew clean bootJar
ls -la build/libs/
```

### Ошибка SSH подключения

Проверьте настройки сервера в скрипте:
```bash
# В начале deploy.sh
SERVER_HOST=${SERVER_HOST:-"REDACTED_IP"}
SERVER_USER=${SERVER_USER:-"root"}
SERVER_PASS=${SERVER_PASS:-"REDACTED_PASSWORD"}
```

### Ошибка Docker на сервере

Убедитесь, что Docker установлен и запущен на сервере:
```bash
ssh root@REDACTED_IP "docker --version && docker-compose --version"
```

### Проблемы с переменными окружения

Проверьте, что `.env` файл содержит все необходимые переменные:
```bash
cat .env
```

## Структура проекта

```

├── deploy.sh              # Основной скрипт деплоя
├── check-deploy.sh        # Скрипт проверки готовности
├── docker-compose.yml     # Конфигурация Docker
├── Dockerfile            # Образ Docker
├── docker-entrypoint.sh  # Точка входа контейнера
├── build.gradle          # Конфигурация сборки
├── .env                  # Переменные окружения
├── env.example           # Пример переменных
└── src/                  # Исходный код
```

## Безопасность

⚠️ **Важно**: 
- Не коммитьте `.env` файл в Git (он должен быть в `.gitignore`)
- Используйте сильные пароли для сервера
- Регулярно обновляйте зависимости
- Мониторьте логи на предмет подозрительной активности
